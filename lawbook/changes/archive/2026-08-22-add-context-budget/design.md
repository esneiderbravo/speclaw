# Design — add-context-budget

## Approach

Treat context cost as a **first-class, measured product surface**, then apply
only levers the MCP server actually controls.

1. **`src/shared/tokens.ts`** — deterministic `estimateTokens(text)` (monotone,
   stable, no network). Calibrated against Anthropic's tokenizer on speclaw's
   own asset corpus (±8% target); documented as an estimator, not a tokenizer.
2. **`src/shared/budget.ts`** — `measureBudget(projectPath, opts)` walks the
   four surfaces and returns structured counts. Tool cost = name + description +
   `JSON.stringify` of the JSON Schema the SDK would send (via the same Zod →
   JSON Schema path registration uses).
3. **`token-budget.json`** (repo root) — declared ceilings. Raising a number is
   a reviewable PR. The suite test asserts `actual ≤ declared`.
4. **`defineTool()`** in `src/shared/mcp.ts` — single registration choke point:
   word-count + token-cap checks, then `server.registerTool`. **No**
   `defer_loading` annotation. All module `register.ts` files migrate to it.
5. **Exposure profiles** — `full` (default) registers all tools; `minimal`
   skips a documented omit-set (install/lifecycle/setup). Omission is the real
   counterpart to the invalidated "defer" story.
6. **CLI** — `speclaw budget`; doctor section; `init`/`update` `--minimal` +
   `Manifest.minimal`; `SPECLAW_MINIMAL=1` for the server process.
7. **Assets** — lawbook skills → dispatcher + `steps/`; compass template map
   markers; indexer writes the map block.

Layering: measurement and caps live in `shared/` (no module imports). Map
generation stays in `compass/indexer.ts`. CLI commands stay thin.

## Decisions (from explore + corrections)

| Decision | Choice | Rejected alternative |
| :-- | :-- | :-- |
| Defer loading | **Do not use.** Report all registered tools as paid. | Eager/deferred tiers and `defer_loading: true` in `defineTool` (corrections §2.3). |
| Estimator | **Own `estimateTokens`.** Optional `budget --exact` / `npm run budget:calibrate` when an API key is present — never in CI. | Shipping a BPE vocab dependency (multi-MB, model-tied, fights local-first). |
| First ceiling | **Measure after description rewrites, then commit `token-budget.json` from that baseline** (ratchet down later). Publish "budget X / actual Y". | Shipping aspirational 5.4k that assumed deferred tools (would lie). |
| Minimal mode | **Omit registration** of setup/lifecycle tools. | Marking them deferred (client ignores). |
| Minimal tool set | Keep discovery + law loop: `compass_explore`, `compass_search`, `compass_recall`, `lawbook_validate`, `lawbook_sync`, `law_verify`, `speclaw_check`. Omit the rest. | 3-tool ultra-minimal (hurts Compass discovery too hard for v1). |
| JIT skills | **In scope** — dispatcher ≤ declared budget; each step names only the next. | Defer to a follow-up (DoD and anti-skip benefit justify same PR). |
| Compact map | **In scope** — markers in `docs/compass.md`, ≤300 estimator tokens, regenerated by `compass_index`. | Writing the map under gitignored `.speclaw/` (clones would lack it). |
| Path-scoped LAWS | **Out of scope** — needs the hooks/post-compact story end-to-end. | Splitting `LAWS.md` without hooks (saves tokens, loses compliance after compact). |
| Capability split | New **`context-budget`** for measurement/profiles/skills/map; deltas to **`cli`** (command/header) and **`quality-gates`** (suite gate). | Folding everything into `cli` (would bury the gate) or inventing `token-budget` next to `context-budget`. |
| Tool count | **21** today (foundation includes `speclaw_check` + `law_verify`). | Roadmap's "20" / corrections' older counts. |

## Budget surfaces (operational definition)

| Surface | Included | Counts toward declared total? |
| :-- | :-- | :-- |
| A · Tools | Every **registered** tool: name + description + serialized JSON Schema | Yes |
| B · Skills/commands | Skill frontmatter + description; full command bodies | Yes |
| C · Always-on | `CLAUDE.md`, `AGENTS.md`, `LAWS.md`, and the compact map block in `docs/compass.md` when present | Yes |
| D · Path-scoped | `.claude/rules/*` with `paths:` (and similar) | Reported only |

`@imports` in agent docs do **not** reduce surface C — imported content is
loaded with the root file. Document that so authors do not "split for tokens"
without `paths:`.

## Honest reporting

- `speclaw budget` and `doctor` report **registered** tool cost. Minimal mode
  shows the smaller registered set.
- If the host later activates Tool Search, that is outside speclaw's control;
  doctor MAY note the ~10%-of-200k heuristic as advisory only — never claim
  speclaw deferred tools.
- Estimator honesty: README states ±8%, points at calibration script, explains
  why exact BPE is worse for a CI gate.

## Alternatives weighed

1. **Measure-only PR** — faster, but leaves the public number ugly and skips
   controllable wins (descriptions, minimal, JIT). Rejected for v1.
2. **Wait for `tool-surface`** — biggest cut, but needs this measurement first
   and breaks tool names. This change enables that work; it does not replace it.
3. **Profiles that register everything and hope for Tool Search** — unverifiable
   and host-dependent. Rejected.

## Risks

- **Discovery regression in minimal mode** — mitigate by keeping `compass_search`
  / `recall` / `explore` registered; document the omit-set; doctor prints mode.
- **Estimator called "a lie"** — publish methodology and calibration up front.
- **Number becomes a liability** — the gate exists so the number cannot drift
  without a PR that raises `token-budget.json`.
- **JIT step files break flow** — each step must name the next file literally;
  suite test forbids mentioning steps beyond +1.
